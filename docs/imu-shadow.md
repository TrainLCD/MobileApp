# IMU シャドーモード実測手順（#7533）

開発ビルド専用です。実験設定はプロセス終了時にオフに戻ります。本番の到着判定、現在駅、位置情報、ETA の状態には書き込みません。

## 準備

`expo-sensors` をインストールして iOS / Android のネイティブアプリをビルドします。JS のみの更新ではモーションセンサーのネイティブモジュールを利用できません。

1. 実験的機能の設定で IMU シャドーモードを有効にします。
2. 地下鉄の走行画面を開き、実際に停車している駅を選びます。端末は安定した向きで固定します。
3. `IMU記録` を押し、モーションセンサーを許可します。発車した瞬間に `実発車` を押します。
4. 次の停車駅に着いた瞬間に `次駅に実到着` を押します。停車判定には時間がかかるので、停車したまま3秒以上経ってから `次区間を開始` を押します。区間を取り違えた記録は評価から除きます。
5. `記録停止` の後、`JSON書き出し` からファイルを保存します。走行画面を離れる前に書き出してください。記録はメモリに1件だけ保持し、次の記録開始またはプロセス終了で失われます。自動送信はしません。

IMU を購読しない `比較記録` モードでも同じ区間を走行します。画面の明るさ、端末、電池状態、通信条件をそろえてください。電池残量を30秒ごとに取得しますが、短い1回の走行では残量の分解能が不足することがあります。電流・消費電力量の測定は別途必要です。

## 推定と記録

- `useEstimateArrivalTimesRoute` の進行順の全駅から停車駅間の区間を作ります。`getTrackDistance` の駅ペアを利用し、通過駅を含めて距離を積み上げます。接続駅の同一駅グループの連続行は1つの停車地点として扱います。駅間距離の欠損を直線距離で置き換えず、その区間の候補判定を無効にします。
- `DeviceMotion` の重力除去済み加速度を水平面に射影し、実停車を起点に、発車時の持続した加速度から進行軸を校正します。100ms間隔の取得を要求します。端末の回転・横方向の動き・サンプル途絶を検出すると、走行中の推定を無効にします。
- 加速度を積分し、位置と速度を推定します。カルマン予測に ETA を弱い位置観測として加えます。ETA で補正しない IMU 単独距離も保持します。停止中に ETA だけで距離を進めることはありません。
- 到着候補には走行、減速、停止、距離と不確実性の条件を用います。信号待ちと駅停止の完全な識別はできません。出力は到着確定ではなく実験上の候補です。
- JSON の `comparisons` には実発車から計算した ETA 誤差、既存 ETA フェーズの到着誤差、GPS判定の誤差、候補ごとの時刻差、誤検出数・未検出、実到着時の距離誤差を出します。候補と実到着の対応付けは±10秒を仮の基準とします。実到着を記録していない区間では誤検出・未検出を確定しません。
- `motion` にセンサー観測、`observations` に既存判定と推定の1秒ごとのスナップショット、`events` に手動ラベルと候補の変化、`battery` に電池情報を記録します。座標は保存しません。

## 限界と次の検証

30分または20,000センサーサンプルを上限とし、画面を離れる、アプリが非アクティブになる、経路が変わる、オートモードに切り替わる場合は記録を止めます。バックグラウンドのセンサー取得は別実験とします。

加速度バイアスや端末移動によって距離は急速にずれ得ます。推定の不確実性と判定しきい値は未校正の仮値であり、統計的に校正された信頼区間ではありません。駅付近の信号待ち、ゆっくりした端末操作、曲線、乗換、実機でのイベント欠落も評価する必要があります。大江戸線などでの実測が必要です。実測で改善が確認できるまで本番判定には採用しません。

API: [Expo DeviceMotion](https://docs.expo.dev/versions/latest/sdk/devicemotion/)
