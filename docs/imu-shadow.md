# IMU シャドーモード実測手順（#7533）

開発ビルド専用です。実験設定で選んだオン・オフは次回の起動時にも反映されます。

## カナリアでの通常乗車

iOS・Androidの開発版では、鉄道の停車中に走行画面を開くと、駅間距離を取得できた区間でIMU推定を始めます。発車を検出すると「次は」に切り替わります。iOSでは初回にモーション利用を許可してください。最後に受理した測位から10秒を超えた場合、または測位がない場合に、次の停車駅と一致するIMU到着候補を現在駅とヘッダーに反映します。IMU到着後に観測された測位を受理すると通常の駅判定に戻ります。

発車駅と次の停車駅の両方で交通種別が鉄道と確認できた区間が対象です。地下鉄かどうかの路線分類は使いません。発車を検出した後で端末を動かしたり、アプリを一時的にバックグラウンドに移したりして距離推定が止まっても、「次は」の表示は維持します。

バックグラウンド測位が有効な乗車中は、別のアプリの使用中や画面ロック中も、届いたセンサーデータで到着を推定します。センサーの取得間隔が500msを超えた区間では到着を補完しません。Androidでは、この変更を含むネイティブビルドが必要です。

シャドーモードをオンにすると比較記録に切り替わります。以下はその実測手順です。

## 準備

`expo-sensors` をインストールして iOS / Android のネイティブアプリをビルドします。JS のみの更新ではモーションセンサーのネイティブモジュールを利用できません。

1. 実験的機能の設定で IMU シャドーモードを有効にします。
2. 鉄道に乗車し、停車中に路線・方面を選んで走行画面を開きます。現在駅を一意に特定できれば、IMU記録を自動で開始します。iOSでは初回にセンサーの利用を許可してください。現在駅が不明な場合はDO（DevOverlay）のIMU欄で開始駅を確認して手動で開始できます。DOを表示しないレイアウトでは利用できません。
3. 端末の向きをなるべく固定し、発車後は操作しません。発車を自動推定します。
4. 次の停車駅に着いた瞬間にDOの `次駅に実到着` を1回押します。次区間へは3秒以上経過した定期観測で自動移行します。IMUやETAの到着候補だけで次区間へ進めることはありません。信号待ちでは押さないでください。
5. 検証を終えるときは `終了・JSON出力` を押してファイルを保存します。走行画面を離れると記録は停止します。記録はメモリに1件だけ保持し、次の記録開始またはプロセス終了で失われます。自動送信はしません。

IMU を購読しない `比較記録` モードでも同じ区間を走行します。自動開始したIMU記録を終了してから比較記録を開始してください。画面の明るさ、端末、電池状態、通信条件をそろえてください。電池残量を30秒ごとに取得しますが、短い1回の走行では残量の分解能が不足することがあります。電流・消費電力量の測定は別途必要です。

## 推定と記録

- `useEstimateArrivalTimesRoute` の進行順の全駅から停車駅間の区間を作ります。`getTrackDistance` の駅ペアを利用し、通過駅を含めて距離を積み上げます。接続駅の同一駅グループの連続行は1つの停車地点として扱います。駅間距離の欠損を直線距離で置き換えず、その区間の候補判定を無効にします。
- `DeviceMotion` の重力除去済み加速度を水平面に射影し、実停車を起点に、発車時の持続した加速度から進行軸を校正します。100ms間隔の取得を要求します。iOS / Android ともに加速度のネイティブ取得時刻（秒）をミリ秒へ変換し、積分に使います。端末の回転・横方向の動き・サンプル途絶を検出すると、走行中の推定を無効にします。センサーの取得時刻が進まない場合も、1秒ごとの記録時に500msの無配信を検査します。無配信時は記録・表示の候補を無効にします。初回の通知を含め、JSのタイマーが遅延中のセンサー通知より先に実行される場合に備え、次の観測まで推定器の無効化を保留します。無配信が継続するか、取得時刻に500msを超える欠落があれば、その区間の推定を無効にします。
- 加速度を積分し、位置と速度を推定します。カルマン予測に ETA を弱い位置観測として加えます。ETA で補正しない IMU 単独距離も保持します。停止中に ETA だけで距離を進めることはありません。
- 到着候補には走行、減速、停止、距離と不確実性の条件を用います。信号待ちと駅停止の完全な識別はできません。出力は到着確定ではなく実験上の候補です。
- JSON の `comparisons` には自動推定の発車から計算した ETA 誤差、既存 ETA フェーズの到着誤差、OS測位で裏付けられた既存到着判定の誤差（GPS比較）、候補ごとの時刻差、誤検出数・未検出、実到着時の距離誤差を出します。候補と実到着の対応付けは±10秒を仮の基準とします。実到着を記録していない区間では誤検出・未検出を確定しません。発車の `departureSource` は `location`（既存の測位由来アンカー）または `imu`（加速度からの推定）です。発車は手動の正解ラベルではなく、特にIMU由来の場合はETA誤差もIMU推定に依存します。推定できなければ発車時刻・ETA誤差は空欄です。
- GPS比較は既存の到着状態に加え、区間内の新しい受理済み測位と駅の到着圏を確認します。測位なし・古い測位・現在の測位と経路に対する手動駅補正は除きます。新しい受理済み測位や経路に切り替われば比較を再開します。Expo Location の値は衛星GNSS専用ではありません。
- `motion` にセンサー観測、`observations` に既存判定と推定の1秒ごとのスナップショット、`events` に手動到着ラベル・自動発車・候補の変化、`battery` に電池情報を記録します。座標は保存しません。

## 限界と次の検証

30分または20,000センサーサンプルを上限とし、画面を離れる、アプリが非アクティブになる、経路が変わる、オートモードに切り替わる場合は記録を止めます。バックグラウンドのセンサー取得は別実験とします。

加速度バイアスや端末移動によって距離は急速にずれ得ます。推定の不確実性と判定しきい値は未校正の仮値であり、統計的に校正された信頼区間ではありません。駅付近の信号待ち、ゆっくりした端末操作、曲線、乗換、実機でのイベント欠落も評価する必要があります。大江戸線などでの実測が必要です。実測で改善が確認できるまで本番判定には採用しません。

API: [Expo DeviceMotion](https://docs.expo.dev/versions/latest/sdk/devicemotion/)
