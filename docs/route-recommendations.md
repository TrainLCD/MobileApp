# 経路の既定選択

StationAPI の `connectedRoutes` は、区間ごとの `recommendedGroupId` と経路全体の
`totalSeconds` を返します。アプリはこの系統で種別の表示と駅一覧の取得を行います。
評価した快速を各停へ置き換える処理は行いません。

推奨 ID が種別一覧に存在しない経路は選択対象から除きます。ID のない旧 API では
従来どおり各停を優先します。追加した二つのフィールドの検証エラーだけを検出し、
そのフィールドを除いた問い合わせを一度再送します。通信エラーや他の検証エラーは
そのまま返します。対応状況は接続先のクライアント単位で保持します。

直通経路の他種別は手動で選択できます。これらは API が評価した全経路の後ろに
並べます。並べ替え時も、他種別に推奨系統の順位を流用しません。

公開順は StationAPI、MobileApp の順を推奨します。GraphQL の数値 ID に使う
`UInt32` はコード生成で `number` に対応させています。

乗換経路では区間ごとの路線と種別を乗車順に保持します。同一路線で各停から快速へ
乗り換える場合も、後半の系統を路線 ID の重複として削除しません。種別一覧の補足と
キーワード検索にも後半の種別を含めます。通常の一系統の路線一覧の重複排除は維持します。
乗換経路の補足では、同一系統の区間でも路線名を乗車順に並べます。同じ会社の
複数路線を会社名へまとめず、再登場する路線名も残します。通常の種別では、
従来の会社別表示を維持します。

### 経路を選び直したときの乗車路線

種別一覧から別の経路を選ぶと、取得した駅一覧の乗車駅を使って乗車路線を更新します。
乗換経路では最初の区間の乗車駅の路線を優先します。
駅一覧の見出しには、この更新後の路線名を表示します。
列車種別の `line` は行先側の路線なので、乗車路線の決定には使いません。
