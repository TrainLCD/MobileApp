# iOSで粗い生座標が再観測された場合の平滑化

iOSの粗い測位に対する固定係数0.3の平滑化は、配信間隔が長いと生座標への追従が遅れます。駅の近くに測位できたかどうかは、この遅れの補正条件には使いません。

次の条件を満たした場合だけ、係数を測位間隔で補正します。

- 今回と前回の採用済み生座標の報告精度が、どちらも1,500mを超えています。
- 測位時刻の差が1秒以上あります。
- 両座標の変位が、既存の1m分解能の距離計算で0mまたは1mです。
- 今回の測位が既存のETAと速度の棄却を通過しています。

報告精度の数kmを変位の許容幅に使うと、駅間移動や座標の揺れまで再観測として扱ってしまいます。そのため、変位の許容幅は距離計算の分解能に合わせて限定します。実際の停車や測位精度を保証する条件ではありません。

補正後の係数は`α = Δt / (Δt + T)`です。`T`は、既存の係数0.3が1秒間隔で持つ遅れ時間です。1秒間隔では従来と同じ係数になります。1秒未満の連続配信では、係数0.3を維持します。

## 既存処理との関係

過去の#7276では、粗い測位による単発ジャンプを抑制しました。#6917では、低精度帯の固定係数を維持しました。今回の補正は、上記条件を満たす場合に限って適用します。棄却した生座標は確認に使いません。Android、報告精度200〜1,500mの平滑化、速度棄却の連続上限、30秒以上古い基準の再同期は既存の処理を使います。

ETAだけで座標や駅、到着・発車の状態を進める処理は追加していません。新しい測位が届かなければ、この補正は動きません。

## 検証の範囲

`src/store/atoms/location.coarseRepeat.test.ts`では、提示された診断ダンプのサンプル70・72・73・75・76の時刻と、丸めた変位1,195m・0m・1m・339mを使います。過去の生座標と移動方向は記録されていないため、座標は合成しています。実走経路の再現ではありません。

駅リストが空でも追従の遅れが減ること、単発の位置飛びと停車位置周囲の揺れを抑制することを検証します。最後の339mのジャンプは約0.26秒間隔なので、既存の速度フィルターによる棄却を維持します。

同じ誤った生座標が続く場合にも、表示位置はその座標へ早く近づきます。今回の補正で減らすのは平滑化による遅れです。OSから届く座標の誤差や欠測は解消しません。
