# iOS背景補完測位の診断

DevOverlayのコピーボタンで生成するJSONには、前景JSの`heartbeat`と別に、iOSネイティブの`backgroundHeartbeat`を含めます。#7355で追加した背景補完測位の経過を確認できます。診断機能を使うにはiOSアプリの再ビルドが必要です。

## 利用できるかの確認

`availability`が`available`なら、`native`に診断結果を格納します。`unavailable`の場合は`reason`で区別します。

| reason | 意味 |
| --- | --- |
| `unsupported-platform` | iOS以外です。ネイティブの診断APIを呼びません。 |
| `native-method-missing` | 実行中のビルドに診断APIがありません。要求0件とは区別します。 |
| `read-failed` | ネイティブ診断の取得に失敗しました。他の診断項目はコピーできます。 |

## 記録の範囲

`native.scope`は`process`です。イベント回数の`counts`はプロセス起動からの累積で、記録のないキーは0回です。前景復帰やタスクの再登録では消去しません。アプリのプロセスが終了すると消えます。

`recentEvents`には古い順で最大40件を残します。`lastEvents`にはイベント種別ごとの最新1件を残します。通常測位が続いて直近40件から終了イベントが消えても、種別ごとの記録を確認できます。複数の位置情報タスクがある場合、回数は合算します。各イベントの`taskName`でタスクを識別できます。

各イベントには壁時計の`atMs`と単調時計の`uptimeMs`を記録します。権限、前景・背景、省電力状態などもイベント発生時の値です。現在の状態を表す値ではありません。ネイティブ側での取得時刻は`native.capturedAtMs`です。

| イベント | 記録するタイミング |
| --- | --- |
| `entered-background` / `entered-foreground` | 背景移行・前景復帰の通知を受けたときです。 |
| `scheduled` | 補完開始用タイマーを予約したときです。`delayMs`に待機時間を記録します。 |
| `timer-fired` | 補完開始用タイマーのコールバックを実行したときです。 |
| `ineligible` / `start-skipped` | 予約時・開始時に条件を満たさなかったときです。権限や省電力状態などを併記します。 |
| `requested` | 補完用マネージャーを作成する直前です。 |
| `started` | 背景実行権を取得し、`startUpdatingLocation`を呼ぶ直前です。 |
| `recovery-received` / `regular-received` | 補完・通常マネージャーから測位コールバックを受けたときです。通常側は背景中だけ記録します。 |
| `no-fresh-sample` | 補完側のコールバックに、新しく有効な時刻の測位がなかったときです。 |
| `succeeded` | 新しい測位によって補完を終了するときです。`source`で補完側と通常側を区別します。 |
| `timed-out` | 補完待機上限のタイマーを実行したときです。 |
| `expired` | UIKitの背景実行期限切れコールバックを実行したときです。 |
| `background-task-denied` | UIKitの背景タスク識別子が無効だったときです。 |
| `recovery-error` | 補完側のエラーを受信したときです。ドメインとコードを記録します。 |
| `failed` | 継続待機する`locationUnknown`以外のエラーで終了するときです。 |
| `cancelled` | 前景復帰、設定変更、省電力状態の変化、タスク解除で取得中の補完を閉じるときです。`reason`を併記します。 |
| `power-state-changed` / `task-reset` | 端末の省電力状態の通知・タスクのリセット処理に入ったときです。 |

## 読み方と制限

- `scheduled`と`timer-fired`を比較すると、予約後にタイマーのコールバックを実行できたかを確認できます。前景復帰や設定変更でもタイマーを取り消すため、差だけでサスペンドを断定しません。
- `requested`と`started`を比較すると、要求後に背景実行権を取得できたかを確認できます。
- `recovery-received`などの回数はコールバック単位です。各コールバックの測位件数は`sampleCount`に記録します。
- `succeeded`はネイティブ側での新しい測位の受信を表します。JavaScript側の精度フィルター通過や駅到着の確定は表しません。`filter.counts`と併せて確認します。
- 受信イベントには最新測位の時刻と精度を残します。緯度経度はこの追加診断に記録しません。ファイル保存やネットワーク送信は行いません。
- コピー時だけネイティブの履歴を読み取ります。診断用のタイマーや測位要求は追加しません。通常測位の10m制限、補完の開始条件、待機上限は#7355の実装を維持します。
