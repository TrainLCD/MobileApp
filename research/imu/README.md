# 乗車中に走行・停車の判定を比較する

開発版のDOで、既存の発車検出器と固定した停車モデルによる候補を比較します。各方式には同じモーション入力を渡します。停車確率が0.65以上で1秒続くと基準方式が停車を確定します。磁気併用方式では、走行開始後の直近2秒の磁場強度の標準偏差が1.428158 µTを超え、角速度の90パーセンタイルが15度/秒以下なら、その窓の停車スコアを0にします。磁気の欠測時には元のスコアを使います。[乗車時の操作](../../docs/imu-shadow.md#乗車中に停車候補を比較する)

通常のカナリア乗車では「再発車確認」の結果を駅案内に反映します。発着ボタンを押さずに発車表示と到着駅を更新できます。所要時間でも距離推定でも駅を裏付けられない停車では現在駅を据え置きます。

## 公開データによる検証

| 記録 | 駅間の誤停車（基準 → 磁気併用） | 到着前後5秒で切り替わり次発まで維持 |
| --- | ---: | ---: |
| 既存の評価54区間 | 9 → 3回 | 20 → 15／38駅 |
| 未使用の3乗車14区間 | 2 → 1回 | 5 → 4／10駅 |

右列の分母は次発を観測した途中駅です。オフラインの表示評価には暫定走行の終了による停車も含めました。DOでは通常の停車確定器を直接観測します。新しい14区間の基準方式で適時に切り替わった5駅は、いずれも暫定走行の終了によるものでした。磁気による停車抑制はDOの比較で使用します。[基準方式の判定時刻](imu-magnetic-stop-events.csv)・[駅ごとの対比較](imu-magnetic-stop-pairs.csv)

CSVの公開乗車分は Stefan Czybik、Pia Hanfeld、Konrad Rieck による TrainTrack Dataset のセンサー計測と発着注釈から算出した加工データです。匿名区間の識別子は原資料に従います。両CSVを原資料と同じライセンスで提供します。[TrainTrack Dataset](https://doi.org/10.5281/zenodo.22206115)・[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/)

## 再現方法

このディレクトリで実行します。引き継ぎデータには開発記録、各評価群の同期済み入力と固定モデルの予測、基準方式の発着イベントが含まれます。追加3乗車は同じデータディレクトリの `magnetic-stop-validation` にあります。使用した環境はPython 3.14、NumPy 2.5.5、scikit-learn 1.9.1です。

```sh
data="$HOME/Documents/TrainLCD-imu-data"
python="$data/handoff-2026-11-28/venv/bin/python"
out=$(mktemp -d)
"$python" -m unittest test_magnetic_stop
"$python" magnetic_stop.py --dataset "$data" \
  --extra-public "$data/magnetic-stop-validation" --check-domestic --output-dir "$out"
cmp imu-magnetic-stop-events.csv "$out/imu-magnetic-stop-events.csv"
cmp imu-magnetic-stop-pairs.csv "$out/imu-magnetic-stop-pairs.csv"
"$python" export_stop_model.py "$data/handoff-2026-11-28/public-eval/fixed-model.pkl" "$out/forest.json"
cmp ../../assets/imu/stop-forest.json "$out/forest.json"
```

モデルの変換時に学習済みファイルのSHA-256を照合します。アプリでは決定木の分岐と葉の確率を読み、端末上で停車確率を計算します。単体テストはリポジトリ直下から `npm test -- --runInBand DevImuArrival imuArrival imuStopTrial ImuShadowPanel` で実行できます。

## 国内の発着記録で端末用の判定器を再生する

都営新宿線5区間、東京メトロ南北線2区間、都営大江戸線1区間のセンサー記録を、DOと同じ判定器に入力しました。基準方式で先頭から約10 Hzに抽出した3乗車を再生すると、到着タップの前後5秒で停車に切り替わり、次の発車まで維持できたのは0／5駅でした。残りの3駅では次の発車を観測していません。市ヶ谷では到着3.28秒後に停車候補を出しましたが、4.58秒後に走行へ戻りました。六本木一丁目では到着12.12秒前に停車候補を出しました。3乗車には磁気の記録がなく、基準と磁気併用の結果は一致しました。

次のコマンドはリポジトリ直下で実行します。同じ乗車の抽出開始位置をずらした再生も含め、国内の停車スコア16,424件と基準方式のすべての状態遷移を保存済みの結果と照合します。基準と再発車確認の走行時間、誤発車、適時に維持できた停車は実発着の目印を使って駅ごとに採点します。スコアの絶対誤差の許容値は `1e-10` です。

```sh
data="$HOME/Documents/TrainLCD-imu-data"
out=$(mktemp -d)
./node_modules/.bin/tsc --ignoreConfig src/lib/imuStopTrial.ts --module node16 \
  --target es2022 --skipLibCheck --types node --resolveJsonModule \
  --esModuleInterop --rootDir . --outDir "$out"
node research/imu/check-ride-stop-trial.mjs "$out/src/lib/imuStopTrial.js" "$data" restart-validation
```

## 停車直後の誤発車を抑える方式

「再発車確認」には基準方式と同じ発車検出器と停車スコアを使います。停車を確定したあと、水平加速度が0.3 m/s²未満で角速度が15度/秒以下の状態が1秒続くと、発車検出を再開します。端末を動かし続けた場合にも発車を拾えるよう、待ち時間の上限は2秒としました。初回の発車は基準方式と同じ条件です。

| 乗車記録（基準 → 再発車確認） | 停車中の誤発車 | 到着前後5秒で切替・次発まで維持 | 実走行中に走行と判定した時間 | 停車中に走行と判定した時間 |
| --- | ---: | ---: | ---: | ---: |
| 国内3乗車8区間 | 2 → 1回 | 0 → 1／5駅 | 720.5 → 705.4／782.5秒 | 124.4 → 100.3／148.7秒 |
| 既に評価した公開54区間 | 11 → 4回 | 14 → 16／38駅 | 1,913.0 → 1,861.4／3,709.2秒 | 192.4 → 176.3／1,206.7秒 |
| 既に評価した追加14区間 | 0 → 0回 | 0 → 0／10駅 | 200.8 → 200.8／1,056.0秒 | 44.0 → 44.0／323.6秒 |
| 条件を固定してから評価した公開3乗車18区間 | 6 → 1回 | 7 → 9／13駅 | 700.9 → 700.9／1,312.0秒 | 58.7 → 46.5／414.5秒 |

通常の停車確定だけを数え、初回の発車を検出するまでは判定待ちとしました。国内では市ヶ谷の停車を次発まで維持でき、九段下の誤発車は残りました。新しい18区間で差が出たのは3乗車のうち1乗車です。駅間の誤停車は両方式とも3回でした。公開データの路線と事業者は匿名です。[TrainTrack Dataset](https://doi.org/10.5281/zenodo.22206115)

国内記録の再生コマンドの最後の引数に `restart-validation` を渡すと、上記の新しい3乗車も駅ごとに採点します。国内3乗車だけを再生するときは、この引数を省略します。

国内3乗車を通常の乗車画面のセンサー購読に入力して、時刻の目印は採点だけに使いました。GPS・駅間所要時間・距離をすべて外した条件では、新宿線の停車判定をそのまま次の駅へ割り当てると、小川町に実到着の211.22秒前に進みました。駅を裏付けられない場合に現在駅を据え置くと、同じ3乗車で推測だけの駅送りは0件でした。実発着時刻と判定そのものには上表のずれが残っています。

以前のTrainLCDの乗車記録4本には、全停車駅の経路、駅間所要時間、距離、端末の計測時刻と手動到着が残っています。位置情報を与えず、最初の乗車駅から走行画面に全モーションを順番に入力しました。正解のタップで現在駅を補正していません。現在駅の自動更新は手動到着21駅中21駅で該当駅と一致し、19駅がタップの前後5秒以内でした。範囲外の2駅は6.18秒早い更新と5.40秒遅い更新でした。大江戸線の2記録では9駅すべてが前後5秒以内でした。同じ入力で新しい判定器の出力を外すと、距離推定だけによる更新は0駅でした。この4記録は停車モデルの開発にも使っています。
